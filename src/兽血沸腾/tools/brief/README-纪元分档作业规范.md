# 纪元分档改写作业规范

## 你在做什么

`世界书/角色/<名>/基础信息.yaml` 现在写的是这个角色的**终局状态**。玩家可能从荒岛篇开局，
此时该角色还没登场、还没获得那些头衔、还没与主角产生那些关系。你要把这些「未来态」字段
按**章节序号**分档，让每个纪元只看到该纪元真实成立的内容。

## 先读什么

1. `tools/brief/<名>.txt` —— 该角色的全部待分档处（节/键/原文/脚本建议下界）+ 文件全文。
   这是你的工作清单，不要跳过。
2. `世界书/角色/刘震撼/基础信息.yaml` —— **分档范本**（无外门的 Shape A）。
3. `世界书/角色/海伦.列娜/基础信息.yaml` —— **分档范本**（有外门的 Shape A）。

## 硬性技术约束（违反会导致条目渲染失败）

这些文件是 `contents` 注册的条目：`contents=[{content:"---\n<character_basic …>"},{file:…},{content:"</character_basic>"}]`。
因此：

- **只能用内联零声明写法**，不得写 `@@private`，不得写 `const`：

  ```
  <%_ if (getvar('stat_data.剧情.章节序号', { defaults: 0 }) >= 73) { _%>
      身份: 高阶写法
  <%_ } else if (getvar('stat_data.剧情.章节序号', { defaults: 0 }) >= 27) { _%>
      身份: 中阶写法
  <%_ } else { _%>
      身份: 早期写法
  <%_ } _%>
  ```

- 一个条目只能有一个装饰器。这些文件本来就**没有**装饰器，所以你别引入。
- 分支体内的每一行都必须能独立构成合法 YAML 映射项，缩进与同级未分档键一致。
- **不要把两个字段合并进一个分档块**：渲染器只认一个条件行，合并会串味。
- `} else if (...) {` 这一行里的 `{ defaults: 0 }` 自带一个 `}`，渲染器已做括号折叠，
  你照抄上面写法即可，不要试图改写条件形态。

## 阈值怎么定

**`brief` 里的「建议下界」只是脚本的粗猜，不是权威。** 上一轮它被证伪过两次
（`龙力` 猜 500，真值 25；`花界形态` 猜 705，实际该标题是花王、首现 418）。

必须自己从原文核：

```
node src/兽血沸腾/tools/probe-first2.mjs <词1> <词2> …
```
打印每个词的**首现 idx** + 出现行数 + 样例行。首现 idx 通常就是该字段的分档下界。

```
node src/兽血沸腾/tools/probe-last.mjs <词…>
```
打印**最后 6 次**出现，用来判断某个称谓/状态是否到后期才成立。

核阈值时注意：
- **首现行可能是作者的话或别人的话**，不是世界观事实。必须看一眼样例行再定。
  （`龙祭祀` 首现 idx7 其实是作者旁白；`男爵` 首现 idx7 是海伦在说她叔叔。）
- **同名词可能指别人**。`胡须迎客` 出现 15 次全是唐藏法师，与主角无关。
- 首现 idx 只要不是明显误命中，就直接用。拿不准就选一个**偏晚**的值：
  宁可晚一档显示，也不要提前泄漏终局态。

## 「身份要跟着剧情走」

一个字段降档，**它后面的剧情也必须跟着降档**。举例：把 `身份` 从「翡冷翠领主」降到
「流浪祭祀」，同一块里形容他「坐拥领地、调兵遣将」的句子就一起不成立了。

所以每个分档块要写**该纪元自洽的一整套**，而不是把同一个句子删几个词。

参考 `刘震撼/基础信息.yaml` 的 `身份` 五档链：427/342/255/73/else 各自是一句完整自洽的身份。

## 分档粒度

用已有的 9 个纪元窗口做直觉标尺：

| 窗口 | idx | 篇 |
|---|---|---|
| 0 | 0–8 | 荒岛篇 |
| 1 | 9–20 | 胸罩岛篇 |
| 2 | 21–30 | 海上篇 |
| 3 | 31–42 | 多瑙大荒原篇 |
| 4 | 43–58 | 博格村与领地初建 |
| 5 | 59–72 | 翡冷翠领主期 |
| 6 | 73–244 | 纵横·成长期 |
| 7 | 245–704 | 纵横·扩张期 |
| 8 | 705–763 | 纵横·终盘 |

不要求每处都凑满 9 档。**只在该字段真的变化的地方切**：多数字段 2–3 档就够。
如果一个字段从头到尾都成立（例如外貌里的种族特征），**就保持不门控**。

## 内容纪律

- **禁止编造**。每个陈述要么有原文依据，要么是原文的自然概括。
  专有名词（地名/头衔/法术名/组织名）必须有出处，用 `probe-first2.mjs` 验。
- **禁止破折号 `——`**（全文红线）。
- **禁止八股**：`似乎|几乎|仿佛|如同|宛如|好似|犹如`、`涟漪`、`嘴角微微上扬`、
  `眼中闪过一丝`、`心头一震`、`不禁`、`不由自主地`、`不是…而是` 等。全清单见
  `tools/check-banned.mjs` 的 `RULES`。
- **不要用元叙事口吻**（「本条」「如前所述」）。
- 文风贴原作：直白、带战力数字、口语化。

## 绝对不能碰

- `兽血沸腾.txt`（原文）、`故事大纲.yaml`（含 `text:` 逐字引文块）—— **只读**。
- `tavern-cards-state.json`、任何 `forge` 命令、任何 `patch`。
- **不要改任何 `年龄` 字段**。
- **不要新增 `私密.yaml` / `私密阶段.yaml`，不要写任何露骨内容**。本作业只改既有
  `基础信息.yaml` 里的普通设定字段。
- 不要动别的角色目录。

## 完成标准

改完你负责的每个文件后，运行：

```
node src/兽血沸腾/tools/check-ejs.mjs
```

必须 **exit 0**，且输出里不得有 `FAIL`。同时确认你的文件出现 `OK  …: 渲染 N/N 例通过`。

再抽查渲染结果，确认分档真的生效：

```
node src/兽血沸腾/tools/probe-render3.mjs "角色/<名>/基础信息.yaml" <章节序号>
```
在该角色**登场前**的章节应几乎渲染不出他的身份/关系段；登场后逐档变全。

另外跑一次 `node src/兽血沸腾/tools/check-banned.mjs`，必须 `命中 0 处`。

## 交付

回报：每个文件改了几处、用了哪些阈值、每个阈值的原文依据（首现 idx + 样例行原文）、
`check-ejs` 的 OK 行原文。不要只说「已完成」。
