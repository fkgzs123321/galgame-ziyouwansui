# 控制中心交互补全规范

本轮目标：把「只读状态展示」升级为「可操作的控制中心」。玩家在面板上做操作 → 前端改写 MVU 变量 → AI 依变量写正文。

## 一、硬性技术约束

1. **只用 store 双向写**：`const store = useDataStore(); const { 战斗 } = store.data;`
   `defineMvuDataStore` 已做与酒馆变量的双向同步，**不要**自己调 `replaceVariables`。
2. **只改 schema 里已存在的路径**。schema 见 `src/兽血沸腾/schema.ts`；不确定就先 `read` 它。
   禁止新增字段、禁止写 schema 外的键。
3. **改集合（record）字段用键操作**，不要整个替换对象：
   ```ts
   战斗.战报[`第${战斗.回合}回合-${i}`] = { 摘要: text, 我方损失: '', 敌方损失: '' };  // 新增
   delete 战斗.战歌加持[名];                                                        // 删除
   ```
4. **`列()` 用于展示**（record/array 双兼容）；写回时必须用原始 record 键，不能用 `列()` 展开后的下标。
5. **数值钳制**：改数前用 `Math.max/min` 夹在 schema 范围内，避免 zod 报错（如 `好感度` −100~100）。
6. **枚举字段**只能取 schema 里列出的值。已确认的枚举：
   - `主角.阶位`: 无 / 风语祭祀 / 灵魂祭祀 / 战争祭祀 / 权杖祭祀 / 维安大萨满 / 十二主祭 / 红衣大祭司
   - `关系.*.关系阶段`: 初识 / 同伴 / 相知 / 相爱 / 妻子 / 疏离
   - `战斗.阶段`: 未开始 / 布阵 / 交锋 / 鏖战 / 追击 / 撤退 / 结算
   - `领地.附庸族.*.关系`: 融洽 / 稳定 / 紧张 / 对立
   - `系统.难度`: 轻松 / 标准 / 硬核
   - `技能树.领地科技树.*.状态`: 未解锁 / 已解锁 / 成长中
7. **每个操作都要留痕**：改完变量后向对应战报/记录字段追加一条摘要，
   让 AI 知道玩家做了什么。格式统一 `{ 摘要: '…', 我方损失: '', 敌方损失: '' }`（战报）
   或 `{ 对象, 日期, 场景, 摘要 }`（亲密记录），或往 `剧情.分歧记录` 写 `{ 卷, 章节, 内容, 后果 }`。
8. **样式只用 `global.css` 已有类**：`sb-sec` `sb-sec-title` `sb-btn` `sb-btn-song/-life/-terra`
   `sb-tb` `sb-node` `sb-tag` `sb-tag-song/-life/-terra/-void/-bond` `sb-dim` `sb-num`
   `sb-bar` `sb-bar-*` `sb-empty` `sb-scroll` `sb-tier` `sb-grid`。
   需要新类就在该组件的 `<style lang="scss" scoped>` 里加，不要动 `global.css`。
9. **不用 `DOMContentLoaded`**；组件内用 `computed` / `watch`，不要全局副作用。
10. **中文注释**，简洁；注释只解释为什么，不复述代码。

## 二、通用交互范式

### 资源花费（领地类）
```ts
function 花得起(消耗: Record<string, number>) {
  return Object.entries(消耗).every(([k, v]) => (领地.资源[k] ?? 0) >= v);
}
function 扣资源(消耗: Record<string, number>) {
  for (const [k, v] of Object.entries(消耗)) 领地.资源[k] = (领地.资源[k] ?? 0) - v;
}
```
按钮 `:disabled="!花得起(消耗)"`，并显示消耗明细。

### 数值微调（关系类）
用 ±5 / ±10 小按钮，不要用输入框。每次点击后写一条 `已触发互动`（array，`push`）。

### 阶段推进（孕事/建筑/科技）
按 schema 枚举给出「下一阶段」按钮，`已解锁 → 成长中 → 已解锁` 或 `确诊 → 显怀 → 临产 → 分娩`。

## 三、各面板分工

| 面板 | 必须新增的交互 |
|------|----------------|
| SkillTreePanel | 点节点解锁/升级（扣 `技能树` 节点自身 `熟练度`/`等级`）；切换 `解锁` 布尔；新增/删除 `技能树.自定义` 节点（自定义节点含 名称/说明/消耗/状态） |
| TerritoryPanel | 建筑升级（扣 4 种基础资源）；兵力招募与训练（扣 金币/粮食，涨 `数量`/`训练度`）；附庸族关系切换 4 档；资源手动补给 |
| HaremPanel | 孕事阶段推进（确诊→显怀→临产→分娩，分娩后写入 `后宫.子嗣`）；成员关系阶段推进；亲密度 ±；写 `后宫.亲密记录` |
| CharacterPanel | 选中角色后 好感度/信任度 ±，关系阶段推进，`印象` 可编辑 |
| ChroniclePanel | 手动标记 `剧情.已触发事件`；写 `剧情.分歧记录`；`名场面` 归档 |
| PetGearPanel | 魔宠 忠诚 ±；契约签订（未签→已签）；装备 穿戴/卸下 |
| OverviewPanel | 保留现有快捷跳转；补 系统.难度 切换、规则开关 切换、`主角.状态` 增删 |
| BattlePanel | 已有；补 阶段推进按钮（布阵→交锋→鏖战→追击/撤退→结算）、敌方单位增删、结界增删 |

## 四、自查（写完必做）

1. `pnpm build` 必须成功，无 TS/模板报错。
2. `node src/兽血沸腾/tools/check-ui-paths.mjs` 必须 0 处越界路径。
3. 逐个核对：你写的每条路径都在 `schema.ts` 里真实存在，且枚举值合法。
4. 报错返回：改了哪些文件、新增了哪些交互、以及 check-ui-paths 的输出。
